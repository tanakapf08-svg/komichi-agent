# 全アクセスモードと権限表示（v0.4.0）

## モデル

認証済みアカウントがあると起動時にモデル一覧を自動取得する。ログイン成功後・アカウント切替後も自動取得する。Activityの再作成だけでは重複取得しない。モデルはチャット上部で選択し、アカウントごとの前回の選択を暗号化した設定に保存する。モデルが利用不可になった場合は現在の一覧の先頭を選び、取得失敗時は古い一覧で送信しない。

一覧取得はチャット実行とは別のジョブで、権限設定画面をブロックしない。アカウント切替時には古い一覧をクリアし、遅れて届いた別アカウントの結果を破棄する。token refreshの保存処理もアクティブアカウントを切り替えない。

## アプリ側のアクセス対象

| 機能 | 通常モード（初期状態） | 全アクセスモード |
|---|---|---|
| アプリ検索 | 起動可能なアプリ | OSから取得できる同じユーザーのインストール済みアプリ。画面を持たないものも表示 |
| アプリ操作対象 | 本人が個別に選択したもの | 未選択のものと今後追加されるアプリも対象 |
| 起動 | 対象アプリのlauncher画面 | launcher画面がある対象のみ。画面なしのパッケージを無理に起動しない |
| SAFファイル | 本人が選択したファイルの情報 | 同左 |
| 共有ストレージのディレクトリ一覧 | 利用不可 | OS権限がある場合のみ `list_directory` で最大60件の情報を参照 |
| 操作承認・送信前確認 | 必要 | 必要 |
| 保護画面・機密情報・自身の操作UI | 制限あり | 制限あり |
| Shizuku / Root | 本人による別途許可・確認 | 本人による別途許可・確認 |

スイッチを有効にする前に、対象が将来追加されるアプリにも広がることを明示して確認する。無効にすると保存済みの個別アプリ選択に戻る。スイッチでOS権限を勝手に付与・撤回したり、RootやShizukuを自動で許可したりしない。OFFでもOS側の付与済み権限は残る場合があり、OS設定から取り消せる。コード側ではOFF中の共有ストレージ一覧を拒否する。

`QUERY_ALL_PACKAGES`を宣言する。対象が不特定のインストール済み・非launcher・将来追加アプリであるため、固定の`queries`だけでは全モードの検索を実現できない。使用は明示opt-inした全モードに限定する。manifestのこの宣言だけに `QueryAllPackagesPermission` lint例外を付け、他のlintエラーは引き続き検査する。これはGoogle Play公開の適格性を確認したという意味ではなく、本配布はサイドロード用Debug APK。

通常の共有ストレージ一覧にはAndroid 11以降では本人が「すべてのファイルへのアクセス」をOS設定で許可する。Android 8〜10ではREAD_EXTERNAL_STORAGEの実行時許可を使う。外部送信は結果の確認後のみで、ファイルの中身の自動送信は行わない。canonical pathを検証し、共有ストレージ外・他アプリの保護データ・シンボリックリンク経由の逸脱を拒否する。

v0.3.0の [Root専用内部データ操作](root-file-operations.md) は別の固定ツール。Root連携、対象アプリ許可、操作ごとの承認、UID 0が必要。全モードを有効にするだけでは利用できない。許可されたアプリの内部データを端末内の新しい共有ストレージ保存先へコピーできるが、任意shell・システム変更・内容の自動アップロードは提供しない。

「全」はアプリが対応する機能の対象範囲を広げる名称で、Androidのサンドボックスや全システム権限を無制限に解除する機能ではない。カメラ・SMS・連絡先等、機能として使用しない権限は追加しない。v0.4.0のマイクは本人が開始する端末内音声入力のために宣言し、音声入力ボタンからだけ実行時許可を求める。

根拠: [パッケージ可視性](https://developer.android.com/training/package-visibility/declaring)、[すべてのファイルへのアクセスと制約](https://developer.android.com/training/data-storage/manage-all-files)。

## 権限の状態

「接続・権限」の先頭で一覧を開ける。通知許可、停止通知チャンネル、AccessibilityのOS有効化・接続状態、ファイル許可、Shizukuの接続と許可をそれぞれ確認する。設定画面から戻った時・通知／Shizuku許可変更時に更新し、手動更新も可能。

画面取得のMediaProjectionは取得セッションごとのOS確認であり、永続的な「許可済み」と表示しない。[公式の画面取得仕様](https://developer.android.com/media/grow/media-projection)

Rootのアプリ内設定と実際のUID確認は別に表示する。起動時に勝手にsuを呼ばず、本人が確認ボタンから実行した結果を「前回確認」と表示する。未確認をRoot利用可能として扱わない。RootやShizukuの権限はOS・管理アプリの状態変更で失われ得るため、操作時のチェックも維持する。

ツールの個別無効化は「ライブラリ」→「ツール」。AIのカタログと実行器の両方に適用し、全モードでも解除しない。`open_url` のブラウザもアプリ対象許可が必要。テキスト作業スペースはアプリ内の暗号化領域で、全モードや全ファイル権限を必要としない。
